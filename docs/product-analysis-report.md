## 二、用户体验评估

### 2.1 关键路径分析

#### 路径 A：首次使用 -> 创建项目 -> AI 对话

| 步骤 | 操作 | 步数 | 评价 |
|------|------|------|------|
| 1 | 打开应用，看到 HomePage | 0 | 有标题+引导文案 |
| 2 | 在 AIPromptInput 输入需求 | 1 | 直觉，自动创建项目+卡片+跳转画布 |
| 3 | 在画布上看到 AI 对话卡片 | 2 | 自动进入编辑状态 |
| 4 | 在 ChatEditor 中输入并发送 | 3 | Enter 发送 |
| **总步数** | | **3 步** | **达标** |

**问题**：步骤 4 后需要等待数秒到数十秒才能看到回复（非流式），体验断裂。

#### 路径 B：打开已有项目 -> 编辑卡片

| 步骤 | 操作 | 步数 | 评价 |
|------|------|------|------|
| 1 | 侧边栏点击项目 | 1 | 需要先打开侧边栏（如果关闭的话） |
| 2 | 画布加载，双击卡片 | 2 | 进入编辑 |
| **总步数** | | **2 步** | **达标** |

**问题**：项目切换后是否自动跳转到画布视图，取决于 `appView` 状态是否联动，需确认代码。

#### 路径 C：创建新卡片

| 方式 | 步数 | 评价 |
|------|------|------|
| 双击画布 → QuickCreateMenu | 2 | 直觉 |

### 3.2 差异化分析

**本产品独特卖点：AI 原生 + 无限画布 + 完全本地**

这是目前市场上罕见的组合：
1. **AI 原生**：不是在白板上加个 AI 插件，而是从架构层面就以 AI Agent 为核心——Tool Calling 循环、多工具协作、上下文感知画布操作
2. **完全本地**：不需要账号、不需要云服务（除 AI API）、数据在本地 SQLite
3. **桌面级性能**：Tauri 2 比 Electron 轻得多，比纯 Web 应用有更好的文件/系统集成

**必须有（基线功能）**：
- 流式输出、Markdown 渲染、撤销/重做、快捷键——**这些是竞品全都有、用户预期必须存在的**
- 缺了这些，产品不可用

**差异化（独特价值）**：
- AI Agent 直接操作画布（创建卡片、分析图片、生成内容）——**竞品做不到**
- 本地 AI 对话 + 画布空间布局——**独特组合**

**可忽略**：
- 手绘/自由画笔（不是绘图工具）
- 实时协作（个人工具）
- 模板市场（过度设计）

### 3.3 市场痛点

| 痛点 | 频率 | 严重度 | 解决难度 | 本产品能否解决 |
|------|------|--------|----------|----------------|
| AI 对话结果散落各处（ChatGPT/Claude 窗口堆积） | 高 | 高 | 低 | **能** — 画布空间化管理 |
| AI 生图后找不到、不好组织 | 高 | 中 | 低 | **能** — 图片卡片+画布布局 |
| 创意发散需要空间感，线性聊天不够 | 中 | 高 | 中 | **能** — 无限画布就是为此设计 |
| AI 工具要在多个网站间切换 | 高 | 中 | 中 | **能** — 一个工具搞定对话+生图+文本 |
| 数据隐私担忧（对话内容上传到云端） | 中 | 高 | 低 | **能** — 完全本地存储 |

## 四、用户画像

### 4.1 核心画像（个人工具，只有一个用户：你自己）

但从产品思维角度，仍然按画像分析，因为"自用工具"的陷阱是——没有把自己的多个使用场景拆清楚，导致什么都想做又什么都半成品。

| 画像 | 场景 | 核心需求 | 痛点 |
|------|------|----------|------|
| **日常对话者** | 想问 AI 一个问题，快速得到回答 | 流畅的对话体验，Markdown 可读 | 等半天才看到回复，代码块是纯文本 |
| **创意发散者** | 用多张卡片在画布上组织想法 | 快速创建卡片、自由布局、颜色标记 | 没有快捷键，没有撤销，误删无法恢复 |
| **图文创作者** | 让 AI 生成图片，配合文字卡片组织素材 | 图片生成+预览+重新生成 | 图片卡片交互不完整 |
| **知识管理者** | 把 AI 对话的有价值内容整理归档 | 搜索、分类、持久化 | 没有搜索，没有颜色分类 |

### 4.2 用户心理分析

| 维度 | 评估 | 详情 |
|------|------|------|
| **首次体验** | 良好 | HomePage 有引导文案 + AIPromptInput，3 秒内能理解产品用途，但需要先配置 API Key 才能用 AI 功能 |
| **认知负荷** | 低 | 4 种卡片类型命名直觉（AI 对话/AI 图片/文本/便签），功能精简 |
| **习得性** | 中等 | 基本操作（双击创建、右键菜单）符合桌面习惯，但高级操作（Agent 侧边栏、框选）缺乏发现途径 |
| **信任感** | 中等 | UI 用 Tailwind 搭建，整体风格现代，但 AI 回复纯文本显示会显得"粗糙" |
| **控制感** | 偏低 | 无撤销 = 用户会害怕操作；AI 非流式 = 用户不知道在发生什么；无停止按钮 = 用户无法中断 |

### 4.3 "首次使用"关键路径问题

**最大障碍：API Key 配置**

新用户打开应用 → 输入需求 → 发送 → 失败（没有配置 Key）。当前没有在发送前检测 Key 是否存在，也没有引导用户去设置。

建议：
1. 首次打开时，如果 `openai_api_key` 为空，在 AIPromptInput 上方显示提示条 "请先配置 API Key"，点击直接跳转设置
2. 或者在 ChatEditor 发送前检测，无 Key 则弹出 SettingsDialog

## 五、功能缺口与边界分析

### 5.1 核心功能缺口（阻断使用）

| 缺口 | 影响 | 当前状态 | 建议 |
|------|------|----------|------|
| **AI 非流式输出** | 用户等待数秒到数十秒，无任何反馈 | `provider.chat()` 等全量返回 | P0：Rust SSE 流 + 前端逐 token 渲染 |
| **无 Markdown 渲染** | AI 回复的代码/表格/列表全是纯文本 | `<p className="whitespace-pre-wrap">` | P0：react-markdown + rehype-highlight |
| **无撤销/重做** | 误操作无法恢复，用户不敢操作 | 完全没有 | P1：内存快照式 undo/redo |
| **快捷键缺失** | 只有 Ctrl+S，Delete/Ctrl+Z/C/V/A 全无 | 无 | P1：useKeyboardShortcuts hook |

### 5.2 体验缺口（降低使用意愿）

| 缺口 | 影响 | 建议 |
|------|------|------|
| **无搜索** | 卡片多了找不到 | P2：Ctrl+F 内存搜索 + 画布飞行定位 |
| **无颜色标记** | 卡片全是同色，无法分类 | P2：右键菜单加颜色子菜单 |
| **无拖拽导入** | 不能拖图片进画布 | P2：onDragOver + onDrop |
| **无 Vision 能力** | ChatEditor 不能附图 | P2：附图按钮 + Tauri dialog |
| **只支持 OpenAI** | 想用其他 AI 平台 | P2：多 Provider 配置 |

### 5.3 边界场景

| 场景 | 风险 | 评估 |
|------|------|------|
| 100+ 卡片性能 | DOM 渲染可能变慢 | 个人使用一般不超过 50 张，配合 visibleCards 裁剪，可接受 |
| 大文件图片 | 内嵌 base64 可能卡顿 | `save_media` 已经存本地文件 + `convertFileSrc`，OK |
| SQLite 并发写入 | 全局 Mutex 锁序列化 | 单用户无并发问题 |
| API Key 泄露 | 明文存 SQLite settings 表 | 个人电脑，威胁不成立（优化计划已确认不做加密） |
| 第三方 API 停服/涨价 | AI 功能全部依赖外部 API | 见风险评估 |

### 5.4 安全评估

| 风险 | 严重度 | 评估 |
|------|--------|------|
| `save_media` 可读取任意本地路径 | 低 | 本地应用，前端可信，但防御性编程建议限制在 app_data_dir 下 |
| `read_media_base64` 同上 | 低 | 同上 |
| API Key 明文存储 | 低 | 个人电脑，可接受 |
| 无 CSRF / XSS | N/A | Tauri 应用，无 Web 安全上下文 |

## 六、增长与价值分析（个人工具适配版）

> 注：本产品定位为个人工具，传统 AARRR 漏斗不完全适用。改为评估"个人工具价值循环"。

### 6.1 价值循环

```
配置 API Key → 创建项目 → AI 对话/生图 → 在画布上组织 → 积累知识/素材 → 持续使用
                                                ↑                               |
                                                └───────────────────────────────┘
```

**当前断裂点**：
1. AI 对话体验差（非流式+纯文本）→ 用户转回 ChatGPT 网页版 → 不再打开
2. 没有撤销 → 用户不敢大胆操作 → 画布利用率低
3. 没有搜索 → 内容积累后找不到 → 放弃使用

### 6.2 差异化定位

**一句话定位**：把 AI 对话从线性聊天窗口解放到无限画布上，用空间布局组织 AI 创作的全部成果。

**不做什么**：
- 不做协作（个人工具）
- 不做手绘（不是绘图软件）
- 不做知识图谱（不是 Obsidian）
- 不做工作流引擎（不是 n8n/Comfy）
- 不做云服务（不做后端）

**做到极致的一件事**：AI 对话 + 空间化组织的结合体验

### 6.3 个人工具 "商业模式"

| 要素 | 当前 | 分析 |
|------|------|------|
| 价值主张 | 本地 AI 创作画布 | 核心价值清晰 |
| 目标用户 | 自己 | 足够专注 |
| 核心渠道 | 自己编译 | 无分发成本 |
| 收入模式 | N/A（自用） | — |
| 成本结构 | AI API 调用费 | 见成本估算 |
| 关键指标 | "是否每天在用" | 个人工具的北极星指标 |

## 十二、核心结论

### 产品的好消息

1. **架构扎实**：前后端分层清晰，Zustand Store 设计合理，Agent 运行时架构完整且可扩展
2. **功能骨架完整**：画布、卡片、项目、AI Agent、持久化——核心模块都已经跑通
3. **代码质量高**：无 TODO/FIXME，TypeScript 类型完整，Rust 侧代码精简
4. **定位精准**：砍掉了所有不需要的功能，专注于个人本地使用

### 产品的坏消息

1. **"最后一公里"未完成**：流式输出、Markdown 渲染、撤销——这三个功能缺失导致产品从"能跑"到"能用"之间有巨大鸿沟
2. **控制感缺失**：没有撤销 + 没有停止按钮 + 没有快捷键 = 用户（即使是自己）会觉得不安全、不高效
3. **AI 对话体验低于免费竞品**：ChatGPT 网页版免费且有流式+Markdown，如果自己的工具连这个基线都达不到，就不会用它

### 一句话总结

**架构 90 分，体验 40 分。只需要 v1.1 的 6-8 天工作量，就能把体验拉到 80 分，让这个工具真正可以每天用起来。**
