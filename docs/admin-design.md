# AI 无限画布 - 管理后台设计

## 1. 定位

独立 Web 管理端，供运营/管理员使用，与 Tauri 客户端完全分离。
管理端只调用 `/api/admin/**` 接口，复用 Spring Boot 同一套后端。

---

## 2. 技术选型

| 组件       | 选型                       | 理由                                 |
| ---------- | -------------------------- | ------------------------------------ |
| 框架       | React 19 + TypeScript      | 与客户端技术栈统一，降低维护成本     |
| UI 库      | Ant Design 5               | 最成熟的中后台组件库，表格/表单强    |
| 构建       | Vite 6                     | 快速构建                             |
| 路由       | React Router 7             | 标准路由方案                         |
| 请求       | Axios + React Query        | 缓存 + 自动刷新 + 乐观更新          |
| 状态       | Zustand                    | 轻量，与客户端保持一致               |
| 图表       | ECharts (echarts-for-react) | 数据可视化                          |

> 管理端不需要 Tauri，纯浏览器访问，部署为 Nginx 静态文件。

## 6. 权限控制

管理后台使用与客户端相同的 JWT 认证体系，额外校验 `role = ADMIN`。

```
管理员登录 → 获取 JWT → 每次请求携带 Token
                              │
                      Spring Security 校验
                              │
                    @PreAuthorize("hasRole('ADMIN')")
```

- 管理后台登录入口独立（`/admin/login`）
- 管理员账号由超级管理员在系统设置中创建
- 初始超级管理员通过启动脚本 / Flyway 数据迁移创建

## 7. 部署

管理后台为纯静态 SPA，打包为 `/dist` 后挂在 Nginx 下：

```nginx
server {
    listen 443 ssl;
    server_name admin.ai-canvas.com;

    # 管理后台前端
    location / {
        root /app/admin/dist;
        try_files $uri $uri/ /index.html;
    }

    # API 反代到 Spring Boot
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

与客户端 API 共用同一个 Spring Boot 实例，无需额外部署。

## 9. 不做的事

| 不做               | 理由                                 |
| ------------------ | ------------------------------------ |
| 操作审计日志页面   | 初期只在数据库记录，不做 UI 展示     |
| 多级管理员权限     | 只分 超管/普通管理员 两级即可        |
| 在线客服/工单      | 非核心功能，用户量起来后再考虑       |
| 数据库管理         | 直接用 Navicat 等工具，不做 Web 化   |
| 画布内容审核       | 用户本地使用为主，不涉及内容审核     |
