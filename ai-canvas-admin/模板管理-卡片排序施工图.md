# 模板管理 — 卡片排序施工图（方案 A）

> 目标：把 admin「模板管理」从表格改成**卡片网格 + 拖拽排序**，照搬桌面端首页观感。
> 拖卡片 = 改模板顺序，拖标签 = 改分类顺序，松手即存，桌面端拉新即生效。

---

## 1. 最终形态

```

┌──────────────────────────────────────────────────────────┐
│ ⠿平面 11   ⠿视频 8   ⠿详情页 4   ⠿试用 4      ← 标签可拖=分类顺序│
├──────────────────────────────────────────────────────────┤
│ ┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐                  │
│ │[封面]││[封面]││[封面]││[封面]││[封面]│  ← 卡片可拖=模板顺序   │
│ │白底图││三视图││换脸  ││融合  ││模特  │                       │
│ │●上架 ││●上架 ││○下架 ││●上架 ││●上架 │  悬停浮出 编辑/上下架/删除│
│ └──────┘└──────┘└──────┘└──────┘└──────┘                  │
```

**卡片构成**：封面缩略图（16:9，无封面占位）+ 名称 + 上架/下架角标。下架卡片置灰但仍在网格里、仍可拖（admin 要能管下架的，桌面端只是不显示）。悬停浮出三个按钮：**编辑 / 上架·下架 / 删除**。

**两个拖拽区**：① 分类标签栏（横向，拖=分类 sort）② 当前分类的卡片网格（拖=该分类内模板 sort）。一次只显示一个分类的网格 = 跟桌面端一模一样。

## 2. 边界（不改，划死，避免乱）

- **桌面端**：零改动（`WorkflowGrid` 已按 sort 渲染）。
- **数据库**：零迁移（`template.sort` / `template_category.sort` 列和索引都已存在）。
- **新建模板**：仍走本机脚本（seed→传图极境→写库），admin 只管已有模板的排序/上下架/改名/删除。
- **分类管理页（`CategoriesView.vue`）**：保留现有表格做增删改名/上下架（CRUD 用表格够清楚）；分类**排序**改由本页标签拖拽负责。
- **跨分类改派**：不支持拖到别的标签；改分类走卡片「编辑」里的分类下拉（已有）。

## 4. 数据流（排序怎么存）— 关键：全局 sort，整表重排

`template.sort` 是**全局**的；桌面端先按分类分桶、桶内按全局 sort 升序。所以排序写库用**整表重排**，最稳、不会让分类 sort 互相打架：

1. 进页面：`getTemplates()` 拿全部（已按 sort 升序）、`getCategories()` 拿全部分类（按 sort）。
2. 在前端按分类 sort 顺序分桶：`buckets[catKey] = 该分类的模板数组`（不在任何分类的模板进末尾「其他」桶，绝不隐藏）。
3. 拖卡片：`vuedraggable` 直接 v-model 当前桶数组（就地改顺序）。
4. 松手 → **把所有桶按分类顺序拼平 → 完整 id 列表 → `reorderTemplates(ids)`**。服务端赋 `sort = 0..N`。这样各分类在全局 sort 里天然连续、桶内顺序 = 拖拽顺序。
5. 拖标签：`vuedraggable` v-model 分类数组 → `reorderCategories(keys)` → 分类 `sort = 0..N`。

> 桶用可变数组（`reactive` 的 `Record<string, AdminTemplate[]>`），不要用 computed（v-model 需可写）。

## 5. 交互细则

- **整张卡片是拖拽把手**；卡上的「编辑/上下架/删除」按钮 `@click.stop`，不触发拖。卡片本身不绑 click（避免和拖冲突）。
- **保存时机**：松手（`@end`）即调 reorder，乐观更新本地数组；失败弹错并 `load()` 回滚。
- **操作复用**：编辑/上架/下架/删除全部复用 `TemplatesView` 现有的 `openEdit` / `toggleActive` / `removeTemplate`，只是从表格按钮挪到卡片上。
- **空分类**：网格显示「该分类暂无模板」。
- **下架卡片**：`opacity` 调低 + 灰度，角标显「下架」，照常可拖。

## 6. 实施步骤（有序）

1. 后端：加两个 `reorder` 端点 + service 方法 + `listAll` 投影；`mvn -DskipTests package` 编译过。
2. Admin：`npm i vuedraggable@^4.1.0`；加两个 api 方法。
3. Admin：重写 `TemplatesView.vue`（标签拖 + 卡片网格拖 + 卡片操作 + 样式照 `WorkflowGrid` 的 16:9 封面/截断名）。
4. 本地 `npm run dev`（admin :3000 代理 :8090）连本地或线上后端，手测拖拽 + 上下架 + 编辑。
5. 构建：`cd ai-canvas-admin && npm run build`（产物直接进 `ai-canvas-server/.../static/admin`）→ `cd ai-canvas-server && mvn -DskipTests package`。
6. 部署：`deploy.py` scp JAR 到 `/opt/ai-canvas/` + 重启（无迁移）。

## 已知坑（就这俩，记着）

- **改分类即生效，不用动 definition**：`TemplateService.listForClient` 用 `category` **列**覆盖 definition 里的 category（列为权威，见该方法第 47 行）。所以编辑弹窗改分类（写列）桌面端就生效，**无需**双写 definition。唯一边界：把分类**清空成 blank** 时不覆盖、会回退 definition 旧值——要改分类就选另一个，别清空。（旧文档里"双写陷阱"已被此覆盖逻辑取代。）
- **listAll 的 filesort**：无 WHERE 的 `ORDER BY sort` + 选了巨型 `definition` 会 `ERROR 1038`；§3 的投影改动一并根治，别漏。
