# 平面模板试用版 + 提示词封装（障眼法）— 设计与施工图

> 目标：把**全部平面（flat）模板**自动派生出一份「试用版」，试用版的提示词**封装起来不让一眼看见**。
> 用户已拍板的两条边界（2026-06-11）：
> 1. **封装强度 = 障眼法**——不让casual看见即可，**不防高手扒 bundle / 抓包**，**不建服务端生成代理**。
> 2. **范围 = 全部平面模板自动派生**（脚本从现有 ~20 个 flat 克隆，不逐个重导 .aicat）。
>
> 直接收益：**不动后端 Java、不传任何新图**（试用版复用平面模板的封面/参考图 NAS URL），改动集中在「派生脚本 + 客户端解码钩子」。

---

## 0. 一句话方案

> 派生脚本把每个 flat 模板克隆成 `<id>-trial`、归 `trial` 类、对带提示词的卡设 `_locked` 并把 `content` **编码成 `ENC1::乱码`** 存进定义；客户端编辑器靠现成 `_locked` 隐藏输入框，**只在生成拼请求的那一刻 just-in-time 解码**。`curl /api/templates`、localStorage、DOM 里看到的都是乱码，达成「障眼法」。

```
平面模板(flat, content 明文)  ──派生脚本 derive──>  试用版(<id>-trial, content=ENC1::乱码, _locked)
                                                          │  入 aicat.template(复用同封面URL,零上传)
                                                          ▼
   桌面端 GET /api/templates ──> 拿到 ENC1::乱码 ──> 编辑器 _locked 藏框 ──> 用户点生成
                                                          │
                                              build*Request 读 data.content
                                              └─ uncloak() just-in-time 解码 ──> 明文发上游(用户自己的 key)
```

## 1. 现状（为什么现在的「封装」是假的）

6.6 分类大改已落过一版 trial 机制，但**只藏 UI、没藏数据**：

- `scripts/import-aicat-templates.py::lock_prompts()` 给 trial 卡设 `data._locked=true` + `_label`/`_description`；
- 编辑器（`ChatEditor.tsx` L492/634-657 等）读到 `_locked` 就把提示词 `PromptTextarea` 换成一个锁图标卡片；
- **但 `card.data.content` 提示词原文照存**，同时漏在三处：
  1. `GET /api/templates` 是**公开**端点（`TemplateController`），`curl` 即得整段明文；
  2. 桌面端 `templateStore` 的 localStorage 缓存里有明文；
  3. 生成时 `build*Request` 照读 `data.content` 拼进请求（`buildImageRequest.ts:89` 的 `buildFinalPrompt`），DevTools Network 可见。

`entitlements.ts` 顶部注释已自认：「本门禁是客户端约束，技术上可被破解；真正不可绕过需把生成走服务端代理」。本次**不做**服务端代理（用户选障眼法），只把上面第 1、2 条的**明文**变成乱码，第 3 条（生成抓包）按用户要求**不管**。

## 3. 详细设计

### 3.1 障眼编码 `cloak / uncloak`（B）

**要求**：可逆、支持中文（UTF-8）、Python 与 TS 产出完全一致、对非编码文本透传。障眼法，**key 不是秘密**（编进客户端 bundle 即可）。

**算法**（XOR + base64 + marker）：
- `marker = "ENC1::"`
- `encode(s)`：`utf8(s)` → 逐字节 XOR 循环 key → base64 → 前缀 `marker`
- `decode(s)`：不以 `marker` 开头 → 原样返回；否则去前缀 → base64 解 → XOR 循环 key → `utf8 decode`
- `key`：一个固定字符串常量（如 `"ac-trial-cloak-2026"`），两端写死同值。

**Python `scripts/promptcloak.py`**（编码端，派生脚本用）：
```python
import base64
KEY = b"ac-trial-cloak-2026"
MARK = "ENC1::"
def _xor(b: bytes) -> bytes:
    return bytes(c ^ KEY[i % len(KEY)] for i, c in enumerate(b))
def cloak(s: str) -> str:
    if not s or s.startswith(MARK):
        return s
    return MARK + base64.b64encode(_xor(s.encode("utf-8"))).decode("ascii")
def uncloak(s: str) -> str:            # 仅供测试对拍
    if not s or not s.startswith(MARK):
        return s
    return _xor(base64.b64decode(s[len(MARK):])).decode("utf-8")
```

**TS `src/lib/promptCloak.ts`**（解码端，客户端用）：
```ts
const KEY = "ac-trial-cloak-2026";
const MARK = "ENC1::";
const keyBytes = new TextEncoder().encode(KEY);
const xor = (b: Uint8Array) =>
  b.map((c, i) => c ^ keyBytes[i % keyBytes.length]);

/** 解开 ENC1:: 编码的提示词；非编码文本原样透传（普通模板/用户输入无副作用）。 */
export function uncloakPrompt(s: string | undefined): string {
  if (!s || !s.startsWith(MARK)) return s ?? "";
  try {
    const bin = atob(s.slice(MARK.length));
    const bytes = Uint8Array.from(bin, (ch) => ch.charCodeAt(0)); // 0-255 安全
    return new TextDecoder().decode(xor(bytes));
  } catch {
    return s; // 解码失败回退原值，至少不崩
  }
}
// （可选）cloakPrompt 供前端单测对拍，运行时不需要
```
> ⚠ 中文坑：必须走 UTF-8 字节再 XOR 再 base64；浏览器 `btoa`/`atob` 只吃 0-255 字节，所以 XOR 后的字节用 `String.fromCharCode`/`charCodeAt` 桥接（上面已处理）。两端务必同 `KEY`、同 marker、同 XOR 循环口径，改一处必改另一处。

> **想更「像加密」**（可选升级）：把 XOR 换成 AES-GCM（TS `crypto.subtle` + Python `pycryptodome`），key 仍编进客户端。强度对「障眼法」无本质提升、对拍更麻烦，**默认不用**，记此备选。

### 3.2 派生脚本 `scripts/derive-trial-templates.py`（A）

**输入**：`scripts/templates-seed.json`（`import-aicat-templates.py` 的产出，含全部 flat/video/detail 定义）里 `category=="flat"` 的模板。

**对每个 flat 模板 T**：
1. `deepcopy(T)` → `id = T.id + "-trial"`、`category = "trial"`、`description = "试用版：提示词已封装，升级正式版可查看与编辑"`（`name` 保持，封面同 T）。
2. 遍历 `cards`，对 `type ∈ {ai_image, ai_chat, ai_video, ai_tryon, ai_multiangle}` 且 `data.content`（或 `_systemPrompt`/`_promptTemplate`）非空的卡：
   - `data._locked = True`
   - `data._label = data._label or card.title or "模板节点"`
   - `data._description = "试用模板：提示词已封装，升级正式版后可查看与编辑"`
   - `data.content = cloak(data.content)`；若有 `data._systemPrompt`/`data._promptTemplate` 一并 `cloak`。
3. **封面 / `refImages` / 连线 / 坐标全原样**（复用 T 的极境 NAS 哈希 URL → **零图片上传**）。
4. `min_app_version` 设为本次发版版本（见 §3.5）。

**输出**：
- 追加进 `scripts/templates-seed.json` + `src/config/templatesFallback.json`；
- 顺带产出**全部 `-trial` id 列表**（给 §3.4 trial 白名单用），写到 `scripts/trial-template-ids.json`。

**推库**：复用现成 `scripts/seed-templates-db.py`（`ON DUPLICATE` 只刷 `definition`+`cover_url`，**保留 admin 的 is_active/sort/name** → 重跑不会把下架的试用版激活回来）。

**幂等**：id 固定（`<flatId>-trial`），可反复跑。新增/改一个 flat 模板 → 重跑 derive → 对应试用版自动更新。

**接进管线**（仿 relayout 并入 import 末尾的先例）：
```
import-aicat-templates.py  →  derive-trial-templates.py  →  seed-templates-db.py
        (产 flat 等)              (追加 -trial 双胞胎)            (一起推库)
```
> 也可把 derive 作为 import 的最后一步调用，保持「一条命令出全量」。建议先独立脚本、跑通后再并入。

### 3.3 生成解码钩子（C）

**唯一咽喉**：所有生成路径（编辑器手点 + 组运行 + agent）最终都过 `build*Request`，提示词只在那里读 `data.content`。在**每个读 `content` 处**套 `uncloakPrompt`：

| 文件 | 位置 | 改法 |
|---|---|---|
| `services/generation/buildImageRequest.ts` | `buildFinalPrompt` L89 `data.content?.trim()` | `uncloakPrompt(data.content)?.trim()` |
| `services/generation/buildVideoRequest.ts` | `buildFinalPrompt`（同结构，读 `data.content`） | 同上 |
| `services/generation/buildChatRequest.ts` | 读 `data.content`（L~103）+ `data._systemPrompt` | 两处都 `uncloakPrompt(...)` |
| `services/generation/buildTryonRequest.ts` | 若读 `data.content` 则同步；不读则免 | 视实现 |

**铁律**：
- **只在「构建请求」时解码**，**绝不**在模板实例化 / 卡片 data 落地处解码——否则明文会被 `autoSave` 写回用户项目（localStorage/服务端）→ 二次泄漏，且把封装白做。卡片 data 静止态始终保持 `ENC1::` 编码。
- `uncloakPrompt` 对非 `ENC1::` 文本透传 → 普通模板、用户手输、video/multiangle 角度编码全无副作用。
- `_locked` 卡片编辑器本就不渲染 `content`（显示 `_label`/`_description`），**编辑器侧不需要解码**，只在生成时解。

**单测**：`services/generation/__tests__/buildRequests.test.ts` 加 round-trip 断言——构造一张 `content=cloak("真提示词")` 的卡，断言 `build*Request` 产出的 `request` 里是**明文**「真提示词」。这是唯一能自验「编码不漏进静止态、解码只在出口」的手段（UI 像素验不了）。

### 3.4 门禁与可见性（D，多为现成机制）

- **可见性**：`-trial` 是 `category=="trial"`，`entitlements.ts:48 canSeeTemplate` 已做「trial 仅非正式版可见」→ **零改**。正式版用户看不到任何 `-trial`（他们用完整 flat）。
- **可用性白名单**：trial tier 的 `aicat.tier_def.features.templates` 要含全部 `-trial` id。
  - **正解**：derive 产出的 `trial-template-ids.json` → 一条 `JSON_SET` 把 trial tier 的 `features.templates` 设成该 id 数组（仿 `scripts/apply-6.6-golive.py`）。重跑刷新。
  - **可选简化**（少维护，本次先不做）：改 `canUseTemplate` 让 `category=="trial"` 对非正式版直接放行；需把 `category` 透传进函数、改 4 处调用点，留作后续。
- **与现有 4 个手作 trial 对账**：自动派生覆盖 flat 后，`wf-outfit-fusion-trial` / `wf-model-bag-trial` 等与新派生的 `<flatId>-trial` **封面重复**。处理：
  - 自动派生为准，**admin 下架**重复的 3 个手作 trial；
  - `wf-face-merge-trial` 有特殊 gender 锁（`人脸合成` 自带），**瞄一眼**：要么保留手作版、要么 derive 时对它单独保留 gender 参数。这一步需人工判断，不阻塞主流程。

### 3.5 上线闸（防老客户端炸）

解码钩子是**新前端代码**。若把 `ENC1::` 编码推上 PROD 库而老客户端没有 `uncloakPrompt`，老客户端会把乱码当提示词发上游 → 试用卡生成全废。两道闸防住：

1. **`min_app_version` 版本守卫**：全部 `-trial` 模板的 `min_app_version = vX`（本次发版号）。`GET /api/templates?appVersion=` 对低版本**直接过滤掉** → 老客户端根本拿不到 `-trial`，也就拿不到乱码、不会炸（顶多看不到试用版，无破坏）。
2. **flat 本体不编码**：平面模板 content 仍明文，正式版用户路径完全不受影响。

> 实测前：6.6 的 `_locked` 试用机制本身据 memory 也「未发版」，所以**第一个带试用版的发布版 = 第一个带 `uncloakPrompt` 的版本**，天然不存在「老客户端已有 trial」的历史包袱。`min_app_version` 仍设上作为安全带。
