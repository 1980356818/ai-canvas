# AICat 自动化接口(Automation Bridge)——设计与施工图

> **目标一句话**:用户安装成品 AICat 后(无源码),在终端里用 Claude Code / Codex 等 AI 编程工具直接操控软件——建项目、建卡片、连线、跑生成、拿结果——全程不碰内部数据文件。
>
> 形态:应用内置一个**本地自动化接口**(127.0.0.1 HTTP + token),同一套"动词表"同时以 **REST** 和 **MCP** 两种方式暴露;安装目录放一份 `AGENTS.md`/`CLAUDE.md` 操作手册,agent 打开就会自己读。

- 项目/卡片/连线 CRUD 已是干净的 platform 层:`platform/project.api.ts`、`card.api.ts`、`connection.api.ts`。

## 1. 为什么不能让外部 AI 直接写 `data.db`(红线)

直觉方案"反正数据在 SQLite 里,让 codex 直接写库"**禁止**,原因:

1. **并发损坏**:app 运行中持有 WAL 连接,外部进程并发写有撕裂风险。
2. **状态不同步**:zustand store 不监听 DB,直写后 UI 不更新,下次 autoSave 还会把内存态覆盖回去。
3. **schema 是内部实现**:`PRAGMA user_version` 随版本迁移,卡片 `data` JSON 无对外校验,直写=每次升级都坏。
4. **绕过黑箱与门禁**:直写可以伪造会员等级、读出封装提示词——商业规则全废。

→ 唯一对外写入面 = 自动化接口的动词表。这条写进《黑箱封装规则》(§7)。

## 2. 总体架构

```
消费者A:Claude Code / Codex / Cursor (用户终端,无源码)        消费者B:应用内对话面板
   │  ① 读安装目录 AGENTS.md/CLAUDE.md(怎么连、有哪些动词)      (AgentPanel,§9,后续)
   │  ② 读 {data_dir}/automation/bridge.json(端口+token)              │
   ▼                                                                  │
127.0.0.1:{port}  ←─ Rust 内嵌 HTTP server(axum,tokio 已有)          │
   ├── POST /v1/call   统一 RPC:{verb, params}        ← curl 兜底     │
   ├── POST /mcp       MCP streamable HTTP(同一动词表) ← 标准接入     │
   └── GET  /v1/health                                                │
   │                                                                  │
   │  Tauri event "automation:request" / invoke 回包                  │ 进程内直调
   ▼                                                                  ▼
AutomationHost(前端常驻监听器,src/services/automation/host.ts)──→ 同一动词层 verbs/*
   │  按 verb 分发到现有动作 —— 与 UI 完全同一代码路径
   ▼
platform/*.api + stores + cardRunner/groupRunner + autoSave
   ▼
SQLite data.db + media/(唯一写入者仍是 app 自己)
```

**关键决策:动词在前端执行,不在 Rust 重写一遍业务。**
Rust 只做"哑管道"(HTTP ↔ event)。理由:① 建卡/连线/跑生成的全部逻辑、校验、会员门禁、自动保存都在前端,复用=零逻辑分叉;② UI 实时可见(agent 建卡,用户眼看着卡出现);③ 试用/会员门禁天然继承,自动化接口不会成为绕过通道。

## 3. P0——自动化桥(核心交付)

### 3.1 开关与发现

- 设置 → 通用 → **「允许本机 AI 工具控制」**,默认**关**。开启后状态栏常显小角标(用户可感知)。
- 开启时 Rust 启动 server:优先固定端口 **11420**,被占则随机端口;无论哪种,写发现文件:

```jsonc
// {data_dir}/automation/bridge.json   (app 退出/关闭开关时删除)
{
  "port": 11420,
  "token": "a3f9…(32B hex,每次启动随机)",
  "pid": 12345,
  "appVersion": "1.3.8",
  "apiVersion": 1
}
```

- 鉴权:所有请求带 `Authorization: Bearer {token}`。仅绑 `127.0.0.1`。
- 威胁模型(成文,不装更高):同用户本机进程可读 token 文件——与 Chrome remote-debugging / Playwright 同级;默认关 + UI 角标是对应的缓解。

### 3.2 统一信封

```jsonc
// 请求  POST /v1/call
{ "verb": "card.create", "params": { ... }, "requestId": "可选,默认服务端生成" }
// 响应
{ "ok": true,  "requestId": "…", "data": { ... } }
{ "ok": false, "requestId": "…", "error": { "code": "GATED", "message": "试用版仅能使用预设模板" } }
```

错误码(闭集):`DISABLED / UNAUTHORIZED / INVALID_ARGS / NOT_FOUND / GATED / UPSTREAM_FAILED / TIMEOUT / BUSY / INTERNAL`。

### 3.3 动词表 v1(15 个,够用即止)

| 动词 | 参数(摘) | 返回 | 复用的现有代码 |
|---|---|---|---|
| `describe` | — | 动词清单+JSON Schema+appVersion | 静态注册表 |
| `project.list` | — | 项目列表 | `platform/project.api.ts` |
| `project.create` | `title` | `{projectId}` | 同上 `createProject` |
| `project.open` | `projectId` | 画布就绪 | HomePage 打开路径同款 |
| `canvas.snapshot` | `projectId` | 卡片+连线紧凑快照 | `cardStore`/`connectionStore` |
| `card.create` | `type,title,prompt,model?,x?,y?` | `{cardId}` | `createAgentContext().createCard`(扩) |
| `card.update` | `cardId,patch` | — | `updateCard` + `autoSave` |
| `card.delete` | `cardId` | — | 现有删除动作 |
| `connection.create` | `sourceCardId,targetCardId` | `{connectionId}` | `platform/connection.api.ts` |
| `connection.delete` | `connectionId` | — | 同上 |
| `run.card` | `cardId` | `{taskId}`(异步) | `services/cardRunner.runCard` |
| `run.group` | `groupId` | `{taskId}` | `services/groupRunner.runGroup` |
| `task.status` | `taskId` | `{state, progress?, resultRefs?}` | taskManager/tasks |
| `task.cancel` | `taskId` | — | `cancelGroup`/取消路径(P3.2 已做) |
| `logs.tail` | `lines?,sinceTs?` | 结构化日志行 | §8 日志文件 |

约定:
- **异步模型**:`run.*` 立即返回 `taskId`,agent 轮询 `task.status`(生成本来就要 30–200s)。`resultRefs` 返回**自动保存目录里的友好路径**(agent 可直接 `Read` 看图)+ 卡片 id,不返回内部 `media/` 路径。
- 动词表 **additive-only**:v1 动词的语义/参数不破坏性变更,新能力加新动词,`apiVersion` 整数递增。
- 限速:沿用现有 `ipc_limits` 思路,单 token 并发 ≤4、队列 ≤32,超出回 `BUSY`。

### 3.5 P0 验收(curl 脚本,进 CI 冒烟)

```bash

TID=$(call "{\"verb\":\"run.card\",\"params\":{\"cardId\":\"$C2\"}}" | jq -r .data.taskId)
# 轮询 task.status 直到 succeeded,断言 resultRefs[0] 文件存在
```

## 4. P1——MCP 端点 + AGENTS.md

### 4.1 MCP(标准接入,推荐路径)

同一 server 上 `POST /mcp` 实现 **MCP streamable HTTP(无状态模式)**,只需三个 JSON-RPC 方法:`initialize`、`tools/list`(动词表→tool schema)、`tools/call`(转 §3 同一分发器)。不引 SDK,~200 行 Rust。

用户侧一条命令接入:

```bash
claude mcp add --transport http aicat http://127.0.0.1:11420/mcp \
  --header "Authorization: Bearer $(jq -r .token {data_dir}/automation/bridge.json)"
# Codex: ~/.codex/config.toml → [mcp_servers.aicat] url/headers 同上(AGENTS.md 给现成片段)
```

### 4.2 为什么 REST 和 MCP 都要

MCP=零文档发现、类型化工具,是 2026 年 agent 标准;REST `/v1/call`=没有 MCP 配置权限时 curl 即用的兜底,也方便用户写普通脚本。两者共享同一分发器,边际成本≈0。

### 4.3 安装目录 `AGENTS.md`(随包分发,Codex/Claude Code 自动读)

内容骨架(~80 行,中文):

1. 这是什么软件、自动化能做什么/不能做什么(§7 黑箱)
2. 连接步骤:开关在哪 → bridge.json 在哪 → MCP 一行接入 / curl 信封
3. **app 没开怎么办**:`bridge.json` 不存在 → 先启动 `AICat.exe`,等文件出现(≤15s)
4. 动词表速查 + 两个完整示例(建项目+文生图链路;轮询拿结果)
5. 工作流/Prompt 渲染要点摘要(§6 两份文档的浓缩版)
6. 红线:不要碰 `data/` 目录任何文件;结果在 `文件自动保存/` 里读

## 5. P2——工程文件协议(Canvas Spec v1)

让 agent 不必一卡一卡 RPC,声明式一次成图;同时这就是对外的「工程文件协议」文档实体。

```jsonc
// canvas-spec v1(import/export 均此格式;内部 data.db schema 不对外)
{
  "specVersion": 1,
  "title": "电商主图九宫格",
  "cards": [
    { "ref": "p1", "type": "text",     "title": "提示词", "prompt": "白底,极简,产品居中…" },
    { "ref": "i1", "type": "ai_image", "title": "效果图", "model": "auto", "size": "2048x2048" }
  ],
  "connections": [ { "from": "p1", "to": "i1" } ],
  "layout": "auto"          // auto=复用模板 relayout 布局器;或显式 x/y
}
```

- 新动词:`spec.import`(整体校验→事务式创建→返回 ref→id 映射)、`spec.export`。
- 校验失败整单拒绝并报哪个 `ref` 错,不留半成品。
- `ref` 仅 spec 内寻址用,落库仍是 UUID。

## 7. 黑箱封装规则(红线,自动化接口的安全边界)

1. **永不经接口出境**:任何 API Key、登录 token、`settings` 表原值、ENC1:: 封装提示词的明文。`canvas.snapshot` 对封装卡返回 `prompt: "[已封装]"` + `cloaked: true`;此类卡 `card.update(prompt)` 拒绝(`GATED`)。
2. **门禁继承**:动词走 UI 同一代码路径 → 试用版只能跑预设模板、会员等级限制原样生效。automation 不是特权通道。
3. **唯一写入面**:外部程序禁止读写 `data/`(`data.db`/`media/`);结果文件一律从 `文件自动保存/` 读。schema/内部路径随版本变化不另行通知。
4. **设置不可写**:v1 不提供 `settings.*` 动词(API key 配置只能人手在 UI 做)。
5. **网络边界**:server 只绑 127.0.0.1;不做局域网/远程模式(真有需求走用户自己的 SSH 端口转发,不在产品内开洞)。

## 8. 日志追踪方案

- **文件**:`{data_dir}/logs/automation-YYYYMMDD.jsonl`,保留 14 天,启动时清过期。
- **行格式**(每请求一行 + 任务每次状态跃迁一行):

```jsonc
{"ts":"2026-06-13T10:21:03.412+08:00","reqId":"r_8f3a","verb":"run.card","ok":true,"ms":124,
 "projectId":"…","cardId":"…","taskId":"t_77","state":"running"}
{"ts":"…","reqId":"r_8f3a","taskId":"t_77","state":"failed","code":"UPSTREAM_FAILED","msg":"上游 504(已脱敏)"}
```

- **关联键**:`requestId` 贯穿 HTTP→前端 handler→任务事件;`taskId` 贯穿轮询。agent 拿 `logs.tail` 自助排障,客服拿同一文件复盘。
- **脱敏**:写盘前过滤 Authorization/api key 形态字符串(复用现有脱敏思路)。
- 与现有 console 诊断日志(`[GroupRun]` 等)互不替代:console 给开发,jsonl 给外部进程。

## 9. 应用内对话式操控(P3,同一动词层的第二个消费者)

产品形态:软件里的对话面板,用户用自然语言指挥画布("帮我建一组电商主图工作流并跑出来")。

**现状:雏形已存在**——`features/agent/AgentPanel.tsx`(对话 UI)+ `agent/runtime.ts`(tool-calling 循环,`MAX_TOOL_ROUNDS=8`)+ `agent/tools/`(仅 4 个工具:`canvas_operations` 建/改/列卡、生图、生文、识图)+ `agent_sessions` 落库。缺口在工具层太薄:不会建项目、不会连线、不会 `run.group`、不会轮询任务、不会导入 spec。

**设计原则:对话面板不维护自己的工具实现,直接消费 §3 动词层。**

- `agent/tools/` 改造为薄适配器:把 §3.3 的 15 个动词(+P2 的 `spec.import`)按 1:1 映射成 LLM function schema,`execute` 直接进程内调 `verbs/*` 同一分发器(不走 HTTP,不需要 token)。`agent/context.ts` 里与动词层重复的 createCard 等逻辑删除,收编进 verbs。
- 收益:门禁/黑箱/jsonl 日志**一处实现**,对话面板和外部 Claude Code 行为完全一致;P0 做完后这一步只是"换壳"。
- 对话端专属增强(只此三样,不多做):工具执行后**镜头平移到新卡 + 高亮 2s**(UI 副作用,挂在对话端适配器,不进动词层);`spec.import` 前先把计划渲染成卡片清单让用户**确认再执行**(跑=扣费);长任务进度以消息流形式回贴到对话。
- LLM 侧复用现有 `agent/providers`(走用户已配置的极境/Comfly chat 模型,需支持 function-calling);`MAX_TOOL_ROUNDS` 放宽到 24 并支持中途取消,长工作流才跑得完。
- 日志:对话端调用与外部调用同写 `automation-*.jsonl`,`source` 字段区分 `"panel" | "bridge"`。
