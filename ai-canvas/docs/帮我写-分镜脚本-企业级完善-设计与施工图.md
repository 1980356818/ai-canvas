## 0. 一句话结论

> **v1 已实现「能出脚本」，但有一个结构性缺陷让它达不到竞品水准：模型拿到的参考素材是「无标签的一堆图」，所以分析出的 `materials[].ref`（"图1"）是模型瞎编的、和画布真实素材无绑定，生成的脚本也无法精准引用"用第几张图的哪个区域"。**
> 企业级完善 = ①**打通 `@素材标签` 闭环**（复用画布既有 `图1/视频1` 标签喂给模型 → 分析按标签产出 → 生成按标签精准引用 → 序列化保留）；②补齐实测验证的契约（`scenes[]` 多场景 / `title`+`summary` / `product.detected` / 子区域引用 / 多变体）；③加企业级健壮性（步骤级状态机 + 取代防护 + 素材指纹重生 + 校验门 + 计费透明）。

## 3. 架构决策（企业级支柱）

| 维度 | 决策 | 依据 |
|---|---|---|
| 素材标签 | **单一真相 = `computeImageRefSources`**；分析/生成/序列化/UI 全用它产出的 `图N/视频N/音频N` | `useImageRefSources.ts` 已是编辑器 @引用同口径，避免再造一套标签 |
| 喂模型方式 | `buildChatRequest` 加**可选** `labelMedia`，开则在每个媒体 part 前插 `【图1】` 文本标记；默认关 → **ai_chat 零影响** | 守"全仓唯一对话翻译层"铁律，加性、零风险（同 v1 合成卡哲学） |
| 生成步媒体 | 生成步**也带标签媒体**（轻量：可只带缩略/低分），让模型"看着图写引用"，而非盲写 | 实测 da-ai 生成步仍 `load_assets`；纯文本盲写正是当前引用空泛的根因 |
| 脚本真相 | 仍 `script(结构化) → result(markdown)` 单向序列化；下游只认 `result` | 与 v1/ai_chat 一致，下游零改 |
| 健壮性 | 步骤级状态机（idle/running/done/error/stale）落 `card.data`；`runEpoch` 取代防护；素材指纹变更标 insights stale | 企业级可恢复/防脏写 |
| 计费 | 透明预估按**实际将跑步骤**动态列（analyze 必跑 / breakdown 仅开关+有视频 / generate × candidateCount） | 对齐实测三段计费语义；客户端无余额不假装 |
| 持久化 | 仍 `card.data` JSON blob，**无 SQLite 迁移**（type 列 TEXT 无 CHECK，rowToCard 盲转型） | v1 §6 已验证 |

## 5. ★ 核心：`@素材标签` 绑定闭环（四跳，最高优先级）

这是把功能从"能用"提到"竞品级"的命脉。四跳全程用 `computeImageRefSources` 的 `图N/视频N` 当唯一标签：

### 5.1 跳一 — 喂模型带标签（改 `buildChatRequest`，加性 opt-in）

`BuildChatRequestOptions` 加：
```ts
labelMedia?: boolean;   // 默认 false。true: 每个媒体 part 前插一个 {type:"text", text:"【图1】"} 标记
```
实现：`buildChatRequest` 内已用 `computeImageRefSources(card.id, refSlots, refImages, undefined, refVideos)` 得到 `imageOptions`（L128，**现成**）。当 `labelMedia` 为真，按 `resolvedUrl` 在 `imageOptions` 里查到 `label`，在 push/unshift 该媒体 `image_url` 前，先插入 `{type:"text", text:`【${label}】`}`。视频额外标 `（视频）`。
- 顺序契约不变：标记紧贴其媒体；多媒体顺序 = imageOptions 顺序（= 编辑器 @ 列表顺序）。
- **默认 false → ai_chat / cardRunner 全不受影响**（守唯一翻译层）。
- 兜底：查不到 label（理论不会）则不插标记，退化为旧行为。

### 5.2 跳二 — 分析按标签产出（改 `ANALYZE_SYSTEM_PROMPT` + 编排）

- 编排 `runScriptAnalyze` 调 `buildChatRequest(synth, { labelMedia: true })`。
- 触发词改为列出**素材清单**（从 `computeImageRefSources` 取）：`"以下素材已按【图1】【视频1】标注，请逐一分析并在 elements[].mention 用相同标签。"`
- 分析提示词输出 `elements:[{mention, type, role, product_related, description}]`，**mention 必须用给定标签**，禁止新造。

### 5.3 跳三 — 生成按标签精准引用（改生成提示词 + 生成步带标签媒体）

- `runScriptGenerate` 不再丢媒体：用 `buildChatRequest(synth, { labelMedia:true })`，systemPrompt=生成提示词、content=商品洞察文本（含 elements 标签表）。
- 生成提示词强约束（实测原文特征）：
  - "引用素材**只能**用 elements 里给定的 @标签（@图1/@视频1），不得新造标签或泛指。"
  - "若某素材是多格拼图/多角度图，引用时**精确到区域**（如'参考 @图1 右下半身局部图''参考 @图2 背面图'）。"
  - "动态动作优先参考视频类素材（@视频N）。"
  - 每镜 `voiceover` 末尾给 `tone`（语气）；每镜给 `audioBgm` 节奏点。
  - 另出 `title` 与 `summary`。

### 5.4 跳四 — 序列化保留 + 下游可用（改 `scriptSerialize` + 解析回填 mentionRefs）

- `scriptToMarkdown` 把 `@图1/@视频1` 原样写进 markdown（纯文本，不转义）。
- 解析 `parseScript` 用正则 `@(图|视频|音频)\d+` 从 `sceneDialogue` 抽取 `mentionRefs[]` 回填到 shot（驱动 §10 UI 高亮 + §11 下游素材转发）。
- 下游 ai_video 卡读到含 `@图1` 的 result 文本即"知道"要配哪些素材；§11 给"应用脚本时一并转发素材连线"的可选增强。

## 6. 提示词流水线 v2（`lib/scriptPrompts.ts`）

三段全部保持「严格 JSON / 纯文本」+ 防御解析。关键改动：

**① 分析（视觉，带标签）** 输出：
```json
{
  "detected": true,
  "productName": "...", "category": "...",
  "features": ["..."], "sellingPoints": ["..."],
  "targetAudience": ["..."], "usageScenarios": ["..."],
  "elements": [
    {"mention":"图1","type":"image","role":"主体参考","product_related":true,"description":"..."},
    {"mention":"视频1","type":"video","role":"动态参考","product_related":true,"description":"..."}
  ]
}
```
系统提示词要点：你是电商短视频策划；**素材已用【图N】【视频N】标注**；只依据可见内容客观提炼，禁止臆造；`detected` 标识有无明确主推品；`elements[].mention` **必须复用给定标签**；中文；严格 JSON 无多余文字。

**①.5 参考视频拆解（视觉，可选，纯文本）** —— 现状已可用，保留；输出节奏/景别序列/钩子结构，作为生成步「框架参考」。（实测对应 `viral_breakdown`。）

**② 生成（带标签媒体，文本主）** 输出：
```json
{
  "title": "...", "summary": "...",
  "overview": { "styleKeywords": ["..."], "note": "拍摄视角/整体基调，如手持Vlog+闺蜜口吻" },
  "scenes": [ {"name":"...","setup":"...","lighting":"...","mentionRefs":["图2"]} ],
  "shots": [
    {"timeRange":"0-5s","shotType":"...","cameraMove":"...","sceneDialogue":"...（参考 @图1 右上细节）",
     "voiceover":"...","tone":"轻快闺蜜语气","audioBgm":"..."}
  ]
}
```
系统提示词在 v1 基础上**追加** §5.3 的标签/子区域/语气/title-summary 约束 + 多场景要求；时长拆镜逻辑（每镜 4-15s、累计时间轴）保留。

**candidateCount>1**：在 system 末尾要求"返回 `candidates:[{…同上…}]` 共 N 条，彼此钩子/节奏差异化"，解析时取数组；=1 时维持单对象（向后兼容）。

## 7. 解析与校验 v2（`lib/scriptParse.ts`）

- `parseInsights`：读 `elements`（新）→ 失败回退读老 `materials` 并 migrate 成 `{mention:"图${i+1}", type, description}`；补 `detected`（缺省 `productName?true:false`）。**mention 白名单校验**：若模型造了不在素材清单里的标签，归一化或丢弃。
- `parseScript`：读 `scenes[]`（新）→ 老 `sceneLighting` 单对象 migrate 成 `scenes:[{name:"",setup:scene,lighting}]`；读 `title/summary`（缺省空串）；每 shot 抽 `mentionRefs`（正则）。
- **校验门（新，企业级）**：
  - 镜头时长校验：解析 `timeRange` 求每镜秒数，越界（<4 或 >15）或时间轴断裂 → 记 `warnings[]`（不阻断，UI 黄条提示，可"重新生成"）。
  - 标签校验：脚本引用的 @标签必须 ⊆ 素材清单；越界标签计入 warnings。
  - 全空/0 镜 → 抛 `ScriptParseError` 触发重试（现有）。
- 解析失败重试：现有 1 次重试保留；重试提示词追加上次错误摘要（"上次输出含非法标签/非 JSON，请仅返回合法 JSON 并只用给定标签"）。

## 8. 编排与健壮性（`services/script/runScriptSteps.ts` + 向导）

企业级韧性（对标 da-ai 服务端 batch 的可观测/可恢复，用客户端等效手段）：

1. **步骤级状态机落库**：`card.data._script: { analyze: StepState; breakdown: StepState; generate: StepState }`，`StepState = { status:"idle"|"running"|"done"|"error"|"stale"; error?:string; at?:string; model?:string }`。每步进入/完成/失败即 `updateCardData`，关弹窗重开按 `_wizardStep + 各 StepState` 精确恢复（含"上次失败可重试"）。
2. **取代防护（runEpoch）**：每次 `runStep` 自增 `epoch`；回调落库前比对 `epoch` 与当前，过期结果**丢弃不写**（防慢分析覆盖新分析）。AbortController 现有，epoch 补"已 abort 但仍 resolve"的竞态。
3. **素材指纹重生**：复用 `collectChatInputs` 思路，对连入素材(url/kind 集合)算指纹存 `_analyzedFingerprint`。向导打开/素材变更时比对，不一致 → 把 analyze 标 `stale` + 顶部黄条"素材已变化，建议重新分析"。同理 insights 改动后 generate 标 stale。
4. **分档模型**：`resolveScriptModel(card, step)`——分析步优先取「支持视觉的高性价比 CHAT 模型」（可在设置加 `script.analyzeModel` 覆盖，缺省走 `resolveDefaultModelForCardType('ai_script')` 但过滤 vision）；生成步可用更强文本模型。先实现"两步可分别选模型"，默认同一个。
5. **统一善后**：沿用 `runStep`（API Key 预检 + friendlyError + finally 清进度，向导 L106 现成）；失败**不写 result/insights/script**，只置对应 StepState=error（保留旧产物）。

## 13. 风险与坑（务必先读）

1. **守唯一翻译层**：`labelMedia` 必须**加性、默认关**；改完跑 `buildChatRequest` 全量单测确认 ai_chat/cardRunner 零回归（否则全仓对话受影响）。
2. **标签顺序一致性**：分析/生成/序列化/UI **必须**都用 `computeImageRefSources` 的同一份标签；若中途素材连线变化导致重新编号，需以"分析时快照的标签集"为准（把标签集随 insights 落库，别每次现算导致漂移）。
3. **生成步带媒体的成本**：生成步从"纯文本"变"带图"，token 上升。缓解：生成步只带**低分/缩略**媒体（da-ai 喂图也 `resize p_30`），或只带 `product_related` 的素材；token 仍可控（实测生成 input<6k）。
4. **多格图区域引用靠模型自觉**：模型可能编造不存在的"区域"。校验只能做标签白名单，区域文字无法校验 → 提示词强约束 + 预览让用户可改。
5. **migrate 一次性**：老卡 `materials/sceneLighting` 读时 migrate，但**写回**用新结构；注意别在每次读都重复 migrate 造成抖动（migrate 后落库一次）。
6. **画布渲染契约**：向导是画布外 modal（安全）；ScriptCard 若加素材高亮动画，遵 `CLAUDE.md` #6（变换层内不放常驻动画）。
7. **candidateCount 上限**：建议 ≤3，防 token 与等待膨胀；UI 明示"按条计费"。
8. **服务端提示词抓不到**：竞品系统提示词原文未知（实测 `input_payload` 恒空），§6 是依据输出契约的**逆向**，按我们语料调优即可，别假设与对方逐字一致。
