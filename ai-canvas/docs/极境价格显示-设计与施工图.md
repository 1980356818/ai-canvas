# 极境价格显示 — 设计与施工图

> 目标：让用户**看得见极境每个模型的价格**。当前软件任何地方都不显示价格。
> **方案（v3，按用户定稿）**：**不进编辑器**，单独做一个**「价格表」页面**（表格），把价格写清楚即可。
> 原则：企业级 = 单一数据源 + 数据驱动 + **每次打开即拉最新**；不要无用功能。
> 所有"服务端返回什么"均 `GET /v1/models*` **实测验证**（2026-06-08），见 §7 附录。

---

## 1. 现状
- 极境模型是前端**静态表**（`src/providers/jijing/models.ts`），无价格字段；`ModelInfo` 类型也无价格位；前端**从不调 `/v1/models`**。价格"看不见"是因为前端从没拿过价格数据。

## 2. 关键发现（决定设计，已实测）

1. **后端零改动**：`GET /v1/models`（不传 platform）一次返回 74 模型含全部价格，覆盖 ai-canvas 所有 SKU。bulk 一次 92KB/~160ms，做表格页一次拉完正合适。
2. **别名要 resolve 成 SKU**：下拉里的 `nano-banana-2/gpt-image-2/...` 是前端别名，服务端 `/v1/models/{alias}`→404；只有 `resolve*()` 解析后的 SKU（`nano-banana-2-4k`…）有价。表格按 `resolve*()` 枚举即可，复用现成函数不漂移。
3. **客户价按 SKU 统一、与线路无关**：每个 SKU 下多条线路（库/M/豆…）的 `pricing.per_request` 是**上游成本+延迟**，不是客户价；客户付的是**顶层代表价**按 VIP 调整（实测 `/vip-pricing` 每档只一个价）。**所以表格每个模型/规格只写一个客户价，不列线路。**
4. **真正的多档价 = ai-canvas 自己的分辨率/画质/tier 选择**：每个组合 resolve 到不同 SKU = 不同价（实测 gpt-image-2 0.112→0.21 / nano-banana 0.21·0.224 / pro 0.336·0.364）。表格把这些档逐行列出。
5. **VIP 自动**：用用户自己的 key 拉 → 拿到的就是该用户 VIP 的真实价，客户端不重算。
6. **实时变动 → 每次打开页面即拉最新 + 刷新按钮**。表格是按需打开的参考页，开即新鲜，无需缓存/TTL，天然解决"价格实时变"。
7. **cost_type 四态，数据驱动展示**（别假设图=张/视频=秒/对话=token）：
   - `PER_REQUEST` → 顶层 `cost_per_request` → `¥0.21` 计费列「每张/每次」
   - `PER_SECOND` → `cost_per_second` → `¥0.05` 计费列「每秒」
   - `PER_TOKEN` / `PER_TOKEN_PREPAID` → `input/output_cost_per_1m` → 价格列「按用量」+ 计费列「入¥X/出¥Y 每百万token」；无费率(seedance)→「按用量」(不写 ¥0)

## 3. 架构（数据流）

```
点左侧控制台胶囊(SideCapsule)「价格」按钮 → uiStore.priceListVisible = true
        ▼
PriceListDialog 打开 → useEffect 拉最新价（每次开都拉）
        │   invoke list_models{provider:"jijing"}（已 GET /v1/models，零 Rust 改动）→ Map<sku, PriceInfo>
        ▼
buildPriceCatalog：遍历 ALL_JIJING_MODELS（=下拉可见集）× 各自 spec 档
        │   复用 resolve*()：(模型, 档) → SKU → Map 查代表价 + cost_type
        ▼
按能力分组渲染表格（图片 / 视频 / 对话）
        列：模型 | 规格 | 价格 | 计费方式      + [刷新] + 「更新于 HH:MM:SS」
```

**为什么是独立页**：价格是只读参考维度；做成一页表格 = 改动最小、最易维护、且"每次打开即最新"顺带解决实时性。**不碰**静态模型表 / 生成管线 / 编辑器 / 画布渲染。

## 6. 边界与降级
1. 某 SKU 查不到价 → 该行价格显「—」+ `console.warn`，**绝不写 ¥0/假价**。
2. PER_TOKEN_PREPAID 无费率 → 「按用量」。
3. 拉取失败/离线/未设 key → 页内显错误态 + 刷新重试，**不影响其它功能**。
4. 海外开关 → base 自动切。
5. VIP → 用用户 key 拉，价已含。

## 附录：实测数据（2026-06-08，测试 key）
- 不传 platform = 74 模型含全价；别名 `/v1/models/{alias}`→404。
- 端点：bulk `/v1/models` 92KB/160ms（表格用这个）。
- 客户价按 SKU 统一（`gpt-image-2-high-4k` /vip-pricing）：FREE 0.21 / VIP1 0.195 / VIP2 0.1875 / VIP3 0.18 / SVIP 0.17。
- 线路=上游成本/延迟（`high-1k` lines：oc0.21/m0.098/md0.21；延迟 gpt334 vs oc1056），非客户价。

**spec 阶梯价：** gpt-image-2 低2K 0.112 / 中2K 0.112 / 高2K 0.168 / 低4K 0.14 / 中4K 0.168 / 高4K 0.21；nano-banana-2 2K 0.21 / 4K 0.224；nano-banana-pro 2K 0.336 / 4K 0.364。

**各 cost_type 代表价：** gpt-5.5 PER_TOKEN 入1.4/出8.4(百万)；gemini-3.1-pro PER_REQUEST 0.06/次；gpt-image-2-official PER_TOKEN_PREPAID 入78.4/出294；seedance-2-0/-fast PER_TOKEN_PREPAID 无费率→按用量；veo3.1-fast-720p PER_SECOND 0.05/秒；veo3.1-pro-1080p 0.15/秒；grok-video-12s PER_REQUEST 0.336/次；Real-ESRGAN 0.035/张；qwen-multipie 0.112/张；omni 1.52/次。

字段：顶层 `id/display_name/capability/cost_per_request/cost_per_second/input_cost_per_1m/output_cost_per_1m/min_vip_level/lines[]`；`/pricing`→`{model,costPerRequest,inputCostPer1mTokens,outputCostPer1mTokens}`；`/vip-pricing`→`{model,tiers[],min_profit_per_request}`。
