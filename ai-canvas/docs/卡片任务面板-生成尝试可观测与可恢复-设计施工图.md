## 施工完成纪要(Phase A,与原设计的差异)

实现时按用户两条新口径调整,并补了一处原设计未点明的机制:

1. **forceAbort 也保活(提前到 Phase A)**:组运行强制中止时,已计费(有 `externalTaskId`)的在途任务不再被浪费 —— 改为 `supersede`(保活,后台跑完进面板),未计费的才 `cancel`。见 [`cardRunner.ts`](../src/services/cardRunner.ts) 的 `onAbort`。

3. **新增 `detach` 机制(并发安全的关键)**:`run()` 的 `completion = Promise.race([loop, detached])`。`supersede` 既标记 `superseded_at` 又 `detach()` 释放等待者,**后台 loop 继续跑到出图**。这让「保活」与「调用方(编辑器/组运行)及时拿回控制权」两个诉求同时成立。配套:`runEditorGeneration` 与 `runCard` 的 `finally` 改为**条件式清进度**(仅当该卡已无活跃任务才清),根治并发尝试里旧 invocation 收尾清掉新任务进度条的竞态。

## 0. 一句话需求

> 卡片**生成中可以随时重新生成**;但旧任务**已经提交上游、已经扣费、无法退款**,所以不应该把它丢掉。要让**每张卡片的所有生成尝试(含被重新生成替换掉的)都能在任务面板里看到,并能逐张把图片保存到本地**。

用户拍板的四个口径(本次已确认,与 lumaxflow 一致):

| 决策点 | 选择 | 含义 |
|---|---|---|
| 旧任务命运 | **保活·后台跑完出图** | 已计费的旧任务不中止,后台静默跑到出图,结果只进面板不写画布 |
| 采纳回画布 | **不采纳·只看 + 存图** | 面板只查看 + 💾保存,不回写画布(单字段模型,天然无竞态) |
| 面板存图 | **要·逐张可存** | 复用现成 `exportFile`/`save_media`,不回写画布、不重新计费 |
| 覆盖范围 | **图片 + 视频(媒体类)** | 媒体本就走任务系统、已有 SQLite 持久化;文本/对话卡留待 Phase C |

## 1. 问题陈述(代码实证)

现状的任务基建其实**很完整**,但"重新生成"这条路上有三个真实缺陷,导致**用户花钱买到的图被静默丢弃**。

### 1.1 重新生成 = 丢图(核心缺陷)

`taskManager.retry()`([`src/services/taskManager.ts:259`](../src/services/taskManager.ts))做三件事:

```ts
if (ACTIVE_STATUSES.has(old.status)) {
  await this.cancel(taskId);          // ① abort 本地轮询
}
await ...upsert({ ...old, status: "orphaned" });  // ② 标 orphaned
return await this.submit({ ...old.request });      // ③ 起新任务
```

而 `cancel()`([`taskManager.ts:232`](../src/services/taskManager.ts))只是 `AbortController.abort()` —— **只停本地轮询,上游图片照样在服务器跑、照样扣了费**,但本仓再也不去取那张图的结果 URL。被标 `orphaned` 的旧任务,在写回桥接器里:

```ts
// src/services/taskBridge.ts:139
case "canceled":
case "orphaned": {
  ...
  failGeneration(task.cardId);         // 清溯源戳,不写结果
  ui.setCardProgress(task.cardId, null);
  return;                               // ← 没有 applyResultToCard
}
```

**净结果:已付费的旧图既不落画布、也不进面板,彻底消失。**

### 1.2 编辑器侧"生成中"被禁止再次生成

各媒体编辑器的生成入口都有 `if (!canGenerate || generating) return;`(如 [`MultiangleEditor.tsx:158`](../src/features/editor/MultiangleEditor.tsx))——**当前根本不允许"生成中再次生成"**。要实现用户的诉求,必须放开这道闸。

### 1.3 任务面板没有"按卡片"视角,也没有保存按钮

`TaskRecordDialog`([`src/features/tasks/TaskRecordDialog.tsx`](../src/features/tasks/TaskRecordDialog.tsx))是一个全局居中弹窗,按"项目 + 状态"过滤、按提示词搜索;`TaskRecordCard` 展示缩略图/状态/进度/时间,有"定位"和"重试"按钮,但**没有"保存图片",也没有"某张卡的全部尝试"分组视角**。

## 2. 设计目标 / 非目标

**目标**
1. 重新生成时,已计费的旧任务**保活**跑到出图,结果进面板可看可存。
2. **根治竞态**:旧任务晚完成绝不覆盖新画布卡。
3. 每张卡有一个**任务抽屉**,列出它的全部生成尝试(含被替换的),逐张💾保存。
4. 放开"生成中再次生成"。
5. 全程**不拦并发**(用户狂点重新生成不受限制)。
6. 崩溃/重启后,保活中的旧任务能**自动续跑**到出图。

**非目标(本期明确不做)**
- ❌ "设为当前/采纳"(把旧尝试回写画布)——只看 + 存图。
- ❌ 文本/对话卡纳入任务系统(Phase C)。
- ❌ App 端展示精确费用数字(后端不参与计费、本地无价格源;只给"已提交上游·已计费"定性徽标。Phase B 视情况补)。
- ❌ 退款(上游已扣,产品层面不退)。

## 3. 核心不变量(三支柱 + 双写闸门)

> 这一节是整个设计的"宪法"。施工时任何改动都不得破坏这四条。

### 支柱 Ⅰ —— 保活(Keep-alive)

> **一旦任务被计费,它的产出绝不浪费。**
> 判据 = `externalTaskId` 已存在(已提交上游),或已是 `success`(同步直返)。
> 这类任务在"被替换/被取消"时**永不 abort**,只打 `superseded_at` 标记,让后台轮询循环跑到 `success`,`finalizeSuccess` 照常 `saveMedia` 把图下载到本地媒体库,结果只进任务面板。
> 反之,**尚未计费**的任务(`queued`、或 `submitting` 但还没拿到 `externalTaskId`)在被替换时**应当 abort**,省掉一次无意义的扣费。

这条天然契合现有状态机:轮询循环只看 `ACTIVE_STATUSES.has(status)`([`taskManager.ts:406`](../src/services/taskManager.ts))。保活 = **不改 status、不 abort,只加 `supersededAt` 旁路标记**,循环自己会跑到底。

### 支柱 Ⅱ —— 写闸门(Write-gate)

> **画布卡的进度/错误/结果,只能被"当前尝试"(`superseded_at IS NULL`)驱动。**
> 被替换的尝试(`superseded_at` 非空)只进任务面板,绝不碰画布卡。

落点(关键):本仓画布卡有**两条**写回路径,**两条都要设闸门**:

1. **桥接器路径** `taskBridge.handleTask`:函数最顶端加 `if (task.supersededAt) return;`。
   - 注意:进度/错误 UI 是**按 cardId** 存的(`ui.generatingCards.get(cardId)`),保活旧任务若不拦会和新任务**抢同一个 cardId 的进度条**。所以闸门必须放在 `handleTask` 最前面(在盖溯源戳、写进度之前)。
2. **编辑器 await 路径**:`runEditorGeneration` 的 `run` 回调在 `await provider.generateImage(...)` 之后会**自己再 `updateCardData` 写一遍**(如 [`MultiangleEditor.tsx:194`](../src/features/editor/MultiangleEditor.tsx),桥接器注释 [`taskBridge.ts:230`](../src/services/taskBridge.ts) 也自认"编辑器的 await 也会写一遍")。保活旧任务跑完时,这条 await 会用**旧图覆盖画布**。必须在 `extractMediaResult` 检出 `supersededAt` 时抛一个**良性的 superseded 信号**,让 `runEditorGeneration` 静默吞掉(不写卡、不报错)。

> **为什么最小闸门 `if (supersededAt) return` 就够(无"进度卡死"边界)**:
> `supersede` 永远与"创建新当前任务"成对出现(见 §6 `beginAttempt`),新当前任务会立刻接管/清理该 cardId 的进度;而真正的"强制中止"(组运行 forceAbort)走的是 `cancel` → `canceled`(**不是** `superseded`),`canceled` 分支照常清 UI。两条路径都不会留下卡死的进度条。

### 支柱 Ⅲ —— 每卡任务面板(CardTaskPanel)

> 右侧抽屉,列出该卡**全部尝试**(按 `attempt_no` 倒序),每条:缩略图 + 状态 + 尝试号 + 耗时 + 提示词 + 💾保存(成功且有媒体时)+ 🗺定位。
> 后台保活任务出图时**实时**冒泡进抽屉(订阅 `tasksStore` 按 cardId 过滤)。

### 数据模型 —— 单轴 `superseded_at`(非双轴)

只加**一个**判据字段 `superseded_at`(`NULL` = 当前尝试,非空 = 被替换),而不是 `is_current` + `orphaned` 双轴。旧的 `orphaned` 状态值**保留**(兼容历史行)但**停止写入**;迁移时把历史 `orphaned`/被替换行回填 `superseded_at`。

新增迁移函数(照本仓 `execute_batch` 风格):

```rust
fn migrate_v13(conn: &Connection) -> Result<(), Box<dyn std::error::Error>> {
    tracing::info!("running migration v13: task attempts (keep-alive + per-card panel)");

    // 生成尝试可观测化:
    //   attempt_no    —— 该卡内尝试序号(1,2,3…),用于面板展示「尝试 #N」与排序
    //   superseded_at —— 单轴「被替换」标记。NULL = 当前尝试(唯一驱动画布卡);
    //                    非空 = 被重新生成替换,已计费的保活后台跑完只进面板。
    //   est_cost / final_cost / currency —— 前向兼容(Phase A 不读不写),
    //                    将来若 App 拿到价格源再填,Phase A 仅显示「已计费」定性徽标。
    conn.execute_batch(
        "
        ALTER TABLE tasks ADD COLUMN attempt_no    INTEGER NOT NULL DEFAULT 1;
        ALTER TABLE tasks ADD COLUMN superseded_at TEXT;
        ALTER TABLE tasks ADD COLUMN est_cost      REAL;
        ALTER TABLE tasks ADD COLUMN final_cost    REAL;
        ALTER TABLE tasks ADD COLUMN currency      TEXT;

        CREATE INDEX IF NOT EXISTS idx_tasks_card_superseded
            ON tasks(card_id, superseded_at);
        ",
    )?;

    // 回填 attempt_no:按 card 内 created_at 升序编号(相关子查询,无窗口函数,可移植)
    conn.execute_batch(
        "
        UPDATE tasks SET attempt_no = 1 + (
            SELECT COUNT(*) FROM tasks t2
            WHERE t2.card_id = tasks.card_id
              AND (t2.created_at <  tasks.created_at
                OR (t2.created_at = tasks.created_at AND t2.id < tasks.id))
        );
        ",
    )?;

    // 回填 superseded_at:每张卡只保留「最新一条」为当前,其余标记被替换。
    // 这样既消化历史 orphaned 行,又保证「每卡至多一个当前尝试」的不变量在迁移后即成立。
    conn.execute_batch(
        "
        UPDATE tasks SET superseded_at = updated_at
        WHERE superseded_at IS NULL
          AND EXISTS (
            SELECT 1 FROM tasks t2
            WHERE t2.card_id = tasks.card_id
              AND (t2.created_at >  tasks.created_at
                OR (t2.created_at = tasks.created_at AND t2.id > tasks.id))
          );
        ",
    )?;

    conn.execute_batch("PRAGMA user_version = 13;")?;
    Ok(())
}
```

> 说明:`ALTER ... ADD COLUMN NOT NULL DEFAULT 1` 给老行填默认 1,再用回填 UPDATE 改成真实序号。回填是 O(n²) 相关子查询,但单用户桌面库 tasks 行数极小,无性能问题。`est_cost/final_cost/currency` 可按需删去(纯前向兼容);保留可省一次将来的 v14。

`tasks_upsert` 的 SQL 在 INSERT 列、VALUES、params、DO UPDATE SET 四处都要加这几列。**关键:`superseded_at` 用 sticky 写法**,防止保活任务后续 `patch`(进度/成功)把已置位的 `superseded_at` 又冲回 NULL:

```sql
INSERT INTO tasks (… , attempt_no, superseded_at, est_cost, final_cost, currency)
VALUES (… , ?19, ?20, ?21, ?22, ?23)
ON CONFLICT(id) DO UPDATE SET
    … ,
    attempt_no    = excluded.attempt_no,
    -- sticky:一旦被置为非空,后续任何 upsert 都不再清回 NULL
    superseded_at = COALESCE(tasks.superseded_at, excluded.superseded_at),
    est_cost      = excluded.est_cost,
    final_cost    = excluded.final_cost,
    currency      = excluded.currency
```

> `created_at`/`updated_at` 维持现状(`updated_at` 由 SQL 刷 `datetime('now')`)。

### 5.2 新命令 `tasks_begin_attempt`(原子开启新尝试)

```rust
/// 开启该卡的一次新生成尝试:把所有「当前(superseded_at IS NULL)」的旧任务
/// 原子标记为被替换,并返回下一个 attempt_no。
///
/// 注意:本命令只动 DB 标记,**不**中止任何在跑的任务 —— 保活由前端
/// TaskManager 决定(已计费的保活、未计费的另行 cancel),见 §6。
#[tauri::command]
pub fn tasks_begin_attempt(state: State<AppState>, card_id: String) -> Result<i64, String> {
    let mut db = state.db.lock().map_err(|e| e.to_string())?;
    let tx = db.transaction().map_err(|e| e.to_string())?;

    tx.execute(
        "UPDATE tasks SET superseded_at = datetime('now'), updated_at = datetime('now') \
         WHERE card_id = ?1 AND superseded_at IS NULL",
        rusqlite::params![card_id],
    )
    .map_err(|e| e.to_string())?;

    let next: i64 = tx
        .query_row(
            "SELECT COALESCE(MAX(attempt_no), 0) + 1 FROM tasks WHERE card_id = ?1",
            rusqlite::params![card_id],
            |row| row.get(0),
        )
        .map_err(|e| e.to_string())?;

    tx.commit().map_err(|e| e.to_string())?;
    Ok(next)
}
```

> 别忘了在 `lib.rs` 的 `tauri::generate_handler![…]` 注册 `commands::tasks::tasks_begin_attempt`(grep `generate_handler!` 找到现有 `tasks_*` 注册处一并加)。

### 5.3 清理与保活的关系(无需改代码,但要确认语义)

- `tasks_list_pending`([`tasks.rs:122`](../src-tauri/src/commands/tasks.rs))按 `status IN (queued,submitting,polling)` 拉恢复清单,**不**过滤 `superseded_at`。所以一个"被替换但仍在 polling"的保活任务,**重启后会被 `resumeAll` 自动续跑到出图** —— 正是我们要的,无需改动。
- `tasks_cleanup_terminal`([`tasks.rs:211`](../src-tauri/src/commands/tasks.rs))删 N 天前的终态行(含被替换的 success)。被替换的尝试历史会在 N 天后随行清掉。**但它只删行、不删媒体文件** —— 保活产出的图会留在媒体库(用户付过费,默认保留)。媒体文件 GC 留到 Phase B(见 §10)。

### 6.1 `startTask` —— 插入"开启新尝试"

```ts
async startTask(spec: TaskSpec): Promise<{ taskId: string; completion: Promise<AsyncTask> }> {
  const handler = this.handlers.get(handlerKey(spec.provider, spec.kind));
  if (!handler) throw new Error(`no handler registered for ${spec.provider}:${spec.kind}`);

  // 保活式「开启新尝试」:把该卡现有「当前」任务标记被替换
  //   • 已计费(有 externalTaskId / 已 success)→ 保活,后台跑完进面板
  //   • 未计费(queued / submitting 无 externalTaskId)→ abort,省一次扣费
  // 返回本卡下一个 attempt_no。
  const attemptNo = await this.beginAttempt(spec.cardId);

  const now = new Date().toISOString();
  const task: AsyncTask = {
    id: crypto.randomUUID(),
    cardId: spec.cardId,
    /* …现有字段… */
    attemptNo,
    supersededAt: undefined,   // 新任务即「当前尝试」
    status: "queued",
    /* … */
    createdAt: now,
    updatedAt: now,
  };

  await useTasksStore.getState().upsert(task);
  const completion = this.run(task, handler);
  return { taskId: task.id, completion };
}
```

新增私有方法:

```ts
/** 开启新尝试:替换旧的「当前」任务(保活/中止),返回下一个 attempt_no。 */
private async beginAttempt(cardId: string): Promise<number> {
  const store = useTasksStore.getState();
  const now = new Date().toISOString();

  for (const t of store.tasks.values()) {
    if (t.cardId !== cardId || t.supersededAt) continue;

    // 先在内存里打 superseded 标记(闸门立刻生效,避免 cancel 触发的 canceled 分支闪一下 UI)
    store.upsertLocalOnly({ ...t, supersededAt: now });

    // 未计费的活跃任务 → 真中止省钱(cancel 内部会 abort + 落 canceled)
    if (ACTIVE_STATUSES.has(t.status) && !t.externalTaskId) {
      await this.cancel(t.id);
    }
    // 已计费 / 已终态的 → 不动,让它后台自己跑完(保活)
  }

  // DB 原子标记 + 取权威 attempt_no
  return await beginAttemptDb(cardId);   // platform: invoke("tasks_begin_attempt", { cardId })
}
```

> `beginAttemptDb` 来自 platform 层(见 §7.1)。内存先标 + DB 再标,两边都置 `supersededAt` 非空,配合 §5.1 的 sticky `COALESCE` 写法,保活任务后续 `patch` 不会把标记冲掉。

### 6.2 `retry` —— 简化(不再 cancel + orphaned)

```ts
/** 重试:直接用同样的 request 起一个新尝试。
 *  旧任务的保活/中止/标记由 startTask → beginAttempt 统一处理,这里不再 cancel/orphaned。 */
async retry(taskId: string): Promise<AsyncTask> {
  const old = useTasksStore.getState().getById(taskId);
  if (!old) throw new Error(`task ${taskId} not found`);
  return await this.submit({
    cardId: old.cardId,
    projectId: old.projectId,
    provider: old.provider,
    kind: old.kind,
    submitEndpoint: old.submitEndpoint,
    pollEndpoint: old.pollEndpoint,
    request: old.request,
    keyTag: old.keyTag,
  });
}
```

### 6.3 `cancel` —— 维持"真中止"语义(被 beginAttempt 与组运行 forceAbort 复用)

`cancel` 本身**不变**(仍是真 abort + 落 `canceled`)。它现在只服务两类调用:
- `beginAttempt` 里对**未计费**任务的中止;
- `cardRunner` 组运行的 **forceAbort**([`cardRunner.ts:233`](../src/services/cardRunner.ts))。

> ⚠ **Phase A 已知取舍**:组运行 forceAbort 仍会真中止当前活跃任务(含已计费的)——即仍会浪费一张已付费图。若要让 forceAbort 也保活,改 `cardRunner` 的 `onAbort` 走"对已计费任务 supersede 而非 cancel"。本期为缩小爆炸半径**暂不改**,列入 Phase B。

## 10. 边界情况与竞态分析

| 场景 | 行为 | 保障 |
|---|---|---|
| 生成中重新生成,新任务先完成 | 新图落画布;旧任务后台跑完→只进面板 | 写闸门①② |
| 生成中重新生成,旧任务后完成 | 旧任务 success 但 `supersededAt` 非空→桥接器闸门 return;编辑器 await 抛 SupersededError 被吞 | 写闸门①② |
| 连点 N 次重新生成 | 每次 `beginAttempt` 替换上一当前;N-1 个已计费的全部后台跑完进面板,最后一个落画布 | 支柱 Ⅰ + attempt_no 递增 |
| 重新生成时旧任务还在 `queued`(未提交) | 旧任务被 abort(省一次扣费),标 superseded+canceled 进面板(无图) | beginAttempt 未计费分支 |
| 崩溃/重启,保活任务还在 polling | `resumeAll` 续跑到出图,进面板 | `tasks_list_pending` 不过滤 superseded |
| 强制中止组运行(forceAbort) | Phase A:真中止当前活跃任务(浪费一张已付费图);Phase B 可改保活 | §6.3 |
| 当前尝试失败 | 画布卡显示错误,但**不**清掉上一张已显示的图(`failGeneration` 只置错不抹 imageUrl) | 现状保持 |
| 删除卡片 | tasks 行 FK `ON DELETE CASCADE` 连带删;媒体文件另算(Phase B GC) | 现状保持 |
| abort 恰逢 submit 在途 | 极小概率上游已扣费但本地拿不到 externalTaskId→记为 canceled(无法追踪的上游孤儿) | 已知极小边界,接受 |

**留存 / 媒体 GC(Phase B)**:保活产出的图(被替换尝试的 success)留在媒体库且不被任何卡引用。`tasks_cleanup_terminal` 只删行不删文件。Phase B 增一个"清理被替换尝试的媒体"动作:删终态 superseded 行时,若其 `result.url` 指向的本地文件**未被任何 card.data 引用**,一并删文件。Phase A 默认保留(用户付过费),可在面板提供手动"清理历史尝试"。

## 13. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 迁移回填把"当前"判错(最新行恰是失败/取消) | `superseded_at` 只影响**今后**的写回与面板标注,不动既有画布内容;可接受 |
| 保活任务堆积(狂点重生成 → N 个后台 poller) | 已付费,poll 退避封顶 10s,成本可忽略;Phase B 可在面板显示"N 个后台进行中" |
| sticky `superseded_at` 写错导致永不可清 | supersede 本就是单向(永不复活),sticky 即正确语义 |
| forceAbort 仍浪费已付费图(Phase A) | 已在 §6.3/§10 标注,Phase B 修 |
| 媒体库随保活产出增长 | 默认保留(用户付费),Phase B 加 GC + 手动清理 |

**回滚**:本设计是纯增量(加列 + 加命令 + 加 UI + 改 4 处逻辑)。回滚 = 还原 `taskManager`/`taskBridge`/`extractMediaResult`/编辑器闸 四处改动即可;v13 加的列留着无害(老代码不读)。
